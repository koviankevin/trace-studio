# v0.1.0 驗證紀錄

初版 14 項測試已通過：串流邊界、UTF-8／跳脫字元、錯誤與截斷 JSON、根陣列與 traceEvents 物件、原始 args 保留、B/E 配對、counter、逆序索引、跨視窗長事件、前後事件、磁碟索引還原、位址正規化、address／define-use／flow 關聯、密集事件聚合與緩衝上限，以及示範 trace 的真實關聯資料。

另以 Node Worker 模擬 Web Worker globals 與 OPFS 方法，驗證正式 worker.js 的 demo／匯入／視窗查詢／事件詳情／關聯／搜尋／相鄰事件／還原／清除通訊，以及 gzip 與損毀檔案錯誤路徑。此替身測試不等於瀏覽器相容性驗證。靜態檢查確認畫面使用的元素 ID 與資產存在，且基準測試的核心來源雜湊仍吻合。

3 GB 同源引擎基準詳見 [PERFORMANCE.md](PERFORMANCE.md)。瀏覽器操作功能 **尚未驗收**：執行環境的本機瀏覽器控制停用，使用者已要求先完成並發布，之後再驗收。

## 待進行的瀏覽器驗收

- 桌面 Chrome / Edge：開啟 JSON／gzip、拖放、取消、錯誤訊息、OPFS quota 不足。
- 快取重新開啟、清除快取、兩個分頁的獨占存取衝突。
- W/S、A/D 的方向與按住加速、Ctrl＋滾輪游標中心、Shift 拖曳平移。
- 單擊選取、F 聚焦、逗號／句號相鄰事件、R 轉區域、調整區域邊界、Q 詳情、Esc 清除。
- Ctrl P 找軌道、Ctrl Shift P 指令選單與鍵盤選擇，輸入框內不攔截一般字母。
- 原始 args、完整 JSON 複製、UTF-8、嵌套物件與巨型參數。
- 位址候選跳轉、連線顯示／隱藏、跨程序相同地址標示不誤導。
- 全覽、最長事件、名稱搜尋、track 篩選與釘選、垂直虛擬化。
- 桌面與窄螢幕、亮／深色、鍵盤聚焦、縮放後字體與按鈕可讀性。
- 真實 3 GB trace：OPFS 解析時間、磁碟空間、峰值記憶體、主執行緒長任務與操作延遲。

通過瀏覽器驗收前，本版仍是初版；文件不得把此清單當成已完成測試。

## 字級調整

依使用者回饋，主要功能文字提高至約 14–16 px、次要資訊至少 12 px；時間軸事件文字由 9 px 提高為 12 px，展開軌道為 13 px，刻度與 counter 標籤為 12 px。同步增加軌道列高、側欄及軌道標籤寬度，刻度密度依可用寬度調整，窄螢幕仍保留可讀字級，側欄可捲動。

本次只改樣式與 Canvas 呈現，不改解析／索引／關聯核心。沿用來源雜湊相同的 3 GB 引擎基準，執行畫面程式語法檢查及發布腳本既有 14 項檢查；正式資產另外核對部署 commit 與檔案雜湊。瀏覽器實際視覺與操作驗收仍依先前安排待進行。

## v0.2.1：開檔啟動與名稱

另用正式 app.js 加 Node Worker 與 DOM／Canvas 替身，驗證啟動示範、選檔、完成後關閉讀取對話框、軌道名稱與事件詳情。這不是實際瀏覽器或 OPFS 驗收。

## v0.2.2：失敗恢復與讀取邊界

## v0.3.0：快取管理與跨分頁協調

新增 session-store.js，統一快取識別碼驗證、讀取有界摘要、獨占 lease 與清理。匯入在建立資料夾之前先取得 session lease，直到關閉檔案才釋放。清理會重新以 ifAvailable 嘗試取得同一把鎖；拿不到便保留資料，不搶占其他分頁。原 OPFS SyncAccessHandle 的獨占鎖仍保留，可辨識舊版分頁的檔案衝突。

快取對話框可列出來源、大小、建立時間、完成狀態與使用狀態，每頁 25 份；可直接還原索引、逐份清理、保留目前 Trace 清理其他未使用資料，或關閉目前 Trace 後清理可刪除資料。清理跳過／失敗的數量會顯示，並同步修正最後 session 指標。清單不讀取原始事件內容，大型舊版 manifest 也不整份解析。

新增六項測試，總數 44 項：

- 正式 Worker 的「清除全部」不刪除另一個 Worker 正在使用的索引；此案例修正前已確認失敗。
- 兩個 Worker 間列出／還原／清理與使用中衝突，終止持有者後可取得鎖並還原。
- 延遲串流重現未完成匯入：匯入中不可清理，終止後可回收殘留資料。
- 清單只取檔案大小與有界摘要，不讀 3 GB raw 或大型 legacy manifest。
- Session 刪除時持有獨占 lease，無法取得時不執行刪除。
- 舊版 metadata、無效 ID 與沒有協作鎖時的未完成快取保護。

另擴充正式 app.js 的 DOM 替身測試，驗證快取清單、從快取切換檔案，以及清理未使用快取後保留目前畫面。兩 Worker 測試使用 Node 的 LockManager 與真實檔案系統替身，仍不等於實際多分頁 OPFS 驗收。解析／關聯核心雜湊未變，沿用 v0.2.1 的 3 GB 引擎測試。

商品等級的剩餘驗收包含實際 Chrome／Edge 多分頁鎖定、快取對話框視覺、真實 3 GB 匯入與操作延遲；先前未完成項目不能因新增替身測試而視為通過。

## v0.3.1：舊版分頁的清理順序

舊版頁面不會持有新的 session lease，但舊版 Worker 會先獨占開啟 events.bin 並持有至關閉。因此清理在取得 lease 後，先對 events.bin 執行單檔移除；若檔案仍被舊版分頁鎖定，即回報 busy，不先遞迴刪除其他 metadata。這是因為 [File System Standard](https://fs.spec.whatwg.org/#api-filesystemdirectoryhandle-removeentry) 明確允許遞迴移除失敗時已刪除部分子檔案。

新增先失敗再通過的舊版忙碌檔案順序測試，總數 45 項；並重驗新協作鎖的兩 Worker 清理、終止後釋放、未完成匯入回收。舊版分頁的使用狀態可能直到實際操作時才由 OPFS 判定；尚未以真實瀏覽器驗收。

## v0.3.2：Counter 極值、邊界與數值尺度

先重現 999／-999 短暫尖峰在聚合後只剩 10 的問題：原摘要與畫素桶都以 duration 選代表，counter 的 duration 全為零，因而留第一筆。改為 counter 專用首尾與 min／max 摘要、保留原始樣本指標、視窗邊界讀取確切索引。舊 manifest 缺少摘要時仍可讀原索引，不需強制清快取。

新增 counter-plot.js，裁切左右相鄰樣本的連線，小數自動尺度與刻度不再捨入成 0.0，常數置中，點選提供原始數值／JSON。插值只產生畫面幾何，不是可選事件或分析樣本。C 事件的 address 關聯改指向有數值的 counter 軌道，避免跳至空白基底軌道；舊關聯索引需重新匯入才能更新。

新增九項測試，總數 54 項：正負尖峰與首尾、部分時間桶、亂序區塊與舊 manifest 的差分核對、相同時間戳跨區塊的相鄰樣本、counter address 跳轉、極小／極大數值與常數的幾何、插值不捏造事件，以及正式 Worker 匯入／細節／還原。擴充 app.js 替身測試，核對 1e-6／2e-6 刻度及點選原始數值。

對最終核心重新執行同規格 3 GB 區段引擎測試；另以 100 萬 counter／四曲線、80 查詢檢查極值與延遲。數據、受測來源雜湊與限制見 [PERFORMANCE.md](PERFORMANCE.md)。這些結果不替代真實瀏覽器與真實 3 GB trace 的驗收。

首次完整發布檢查有 53／54 通過，Windows 暫存目錄清理回報 ENOTEMPTY，因此未推送。事後檢查該目錄只剩空子目錄；測試檔案系統替身與清理改用 Node 原生的有界重試（最多三次、50 ms 線性退避），永久錯誤仍會失敗。遞迴清理前另驗證絕對路徑必須是本次 OS 暫存區下的 trace 測試目錄，不放寬產品中的鎖定或清理判定。

## v0.5.0：多檔保存、門檻快取與 TfliteID 比較

使用者接受大檔切換時重載，要求多份 Trace 保存，並希望小檔保留已載入索引。新增多選／拖放佇列、頂部已保存分頁、最近 50 份瀏覽狀態。Worker 可保留最多三份閒置小檔的完整索引 context，門檻預設 64 MB、可選 0／32／64／128／256 MB，總資料量預算最多門檻兩倍、上限 512 MB。大小採原檔與解壓後事件＋索引較大者，並非 RAM 計量或載入所有 raw Args。淘汰會關閉 handle／lease，不刪 OPFS；大檔或重整後從已保存索引還原。

同 TfliteID 比較支援 2–4 份，依序在 Worker 分析，以各檔該 ID 第一個事件對齊，呈現跨度、差值、inclusive 累計時間、核心、同名事件與記憶體空間。統計掃描全部同 ID 事件，時間圖只顯示索引前 100 筆，ID 重用與截斷限制在畫面及匯出保留。點選時間列可切換並定位事件。比較不替換目前的 DB；閒置小檔使用同 Worker context，大檔暫時開啟後釋放 handle／lease，其他分頁占用則回報該來源錯誤。

本次按儲存與共享狀態影響選測 `app-import`、`argument-analysis`、`integration`、`trace-cache`、`trace-comparison`，19 項通過：
