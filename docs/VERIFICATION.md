# v0.1.0 驗證紀錄

初版 14 項測試已通過：串流邊界、UTF-8／跳脫字元、錯誤與截斷 JSON、根陣列與 traceEvents 物件、原始 args 保留、B/E 配對、counter、逆序索引、跨視窗長事件、前後事件、磁碟索引還原、位址正規化、address／define-use／flow 關聯、密集事件聚合與緩衝上限，以及示範 trace 的真實關聯資料。

另以 Node Worker 模擬 Web Worker globals 與 OPFS 方法，驗證正式 worker.js 的 demo／匯入／視窗查詢／事件詳情／關聯／搜尋／相鄰事件／還原／清除通訊，以及 gzip 與損毀檔案錯誤路徑。此替身測試不等於瀏覽器相容性驗證。靜態檢查確認畫面使用的元素 ID 與資產存在，且基準測試的核心來源雜湊仍吻合。

3 GB 同源引擎基準詳見 [PERFORMANCE.md](PERFORMANCE.md)。瀏覽器操作功能 **尚未驗收**：執行環境的本機瀏覽器控制停用，使用者已要求先完成並發布，之後再驗收。

## 待進行的瀏覽器驗收

- 桌面 Chrome / Edge：開啟 JSON／gzip、拖放、取消、錯誤訊息、OPFS quota 不足。
- 快取重新開啟、清除快取、兩個分頁的獨占存取衝突。
- W/S、A/D 的方向與按住加速、Ctrl＋滾輪游標中心、Shift 拖曳平移。
- 單擊選取、F 聚焦、逗號／句號相鄰事件、R 轉區域、調整區域邊界、Q 詳情、Esc 清除。
- Ctrl P 找軌道、Ctrl Shift P 指令選單與鍵盤選擇，輸入框內不攔截一般字母。
- 原始 args、完整 JSON 複製、UTF-8、嵌套物件與巨型參數。
- 位址候選跳轉、連線顯示／隱藏、跨程序相同地址標示不誤導。
- 全覽、最長事件、名稱搜尋、track 篩選與釘選、垂直虛擬化。
- 桌面與窄螢幕、亮／深色、鍵盤聚焦、縮放後字體與按鈕可讀性。
- 真實 3 GB trace：OPFS 解析時間、磁碟空間、峰值記憶體、主執行緒長任務與操作延遲。

通過瀏覽器驗收前，本版仍是初版；文件不得把此清單當成已完成測試。

## 字級調整

依使用者回饋，主要功能文字提高至約 14–16 px、次要資訊至少 12 px；時間軸事件文字由 9 px 提高為 12 px，展開軌道為 13 px，刻度與 counter 標籤為 12 px。同步增加軌道列高、側欄及軌道標籤寬度，刻度密度依可用寬度調整，窄螢幕仍保留可讀字級，側欄可捲動。

本次只改樣式與 Canvas 呈現，不改解析／索引／關聯核心。沿用來源雜湊相同的 3 GB 引擎基準，執行畫面程式語法檢查及發布腳本既有 14 項檢查；正式資產另外核對部署 commit 與檔案雜湊。瀏覽器實際視覺與操作驗收仍依先前安排待進行。

## 緊湊工作台與多核心分組

依使用者提供的多核心畫面，時間軸改用填滿視窗的工作台：預設收合側欄、大型標題不佔時間軸空間、摘要縮為工具列、一般單層事件列約 32 px，保留 12 px 事件字與 13 px 名稱；巢狀軌道依需要增高。新增可收合程序／核心樹、work 配對排序、群組摘要與可調高的下方事件欄位表。

新增 9 項功能測試，目前總數 23 項：核心前綴識別（不誤把通道數字當核心）、PID 與核心分組、work 排序、收合／篩選／目標展開、釘選唯一性、緊湊與巢狀列高、僅從記憶體摘要產生有界的群組概覽、硬體欄位只保留來源提供的值，以及四核心／每核心 28 軌道的示範與正式 Worker 通訊。

解析與關聯核心未修改；3 GB 引擎基準依來源雜湊沿用，新增群組概覽及新的 UI 並未包含於原效能數據。瀏覽器實際畫面、面板拖曳、階層操作與小螢幕仍待人工驗收。正式部署另核對本次來源與全部靜態資產雜湊。

## v0.2.0：分析、程式擴充與呈現

新增背景分析、範圍／軌道限制、重疊區段裁切、長事件門檻、近似 P95、取消與匯出。新增本機程式擴充介面，可加事件欄位、配色與 Worker 分析；不連內網 API 或遠端 AI。原始欄位預設展開，移除重複 Thread UI 標示，counter 集中成數值曲線群組。

新增 10 項測試，總數 33 項：數值與半開區間／重疊語意、空範圍、資料筆數界線、索引分析不讀 raw args、分批讓出／取消、擴充掃描、擴充錯誤隔離與摘要副本、色彩分類、正式 Worker 分析期間接受視窗查詢、counter 分組來源與釘選。入口與資產檢查涵蓋新模組。

原解析與關聯核心的 SHA-256 未變，沿用原 3 GB 匯入基準；原基準未量測新增分析、自訂擴充或新的畫面。瀏覽器實際操作與效能依既有安排仍待驗收。發布時核對來源 commit 與所有靜態檔，含 extensions 子目錄。

## v0.2.1：開檔啟動與名稱

修正 Worker 在等待擴充模組期間尚未設定 onmessage，導致首個 import／示範／還原請求可能被丟棄的問題。接收器改為同步註冊，已收到的操作再等待擴充初始化。以正式 worker.js 的 VM 模組測試控制擴充的延遲，確認修正前首個檔案訊息遺失、修正後進入實際 import 處理；原有測試都先等待 Worker 初始化，未涵蓋此時序。

另用正式 app.js 加 Node Worker 與 DOM／Canvas 替身，驗證啟動示範、選檔、完成後關閉讀取對話框、軌道名稱與事件詳情。這不是實際瀏覽器或 OPFS 驗收。

移除預設軌道編號前的 #。未命名事件使用來源 thread name，名稱 metadata 在事件之後亦可；一般事件、B/E 與 counter 都保留原始 JSON，明確提供的 Event 名稱不受影響。驗證快取還原、搜尋、相鄰事件與詳情名稱一致。

新增三項測試，總數 36 項；因改動索引名稱處理，重新量測相同規格 3 GB 引擎基準，結果與來源雜湊另存 v0.2.1 紀錄。瀏覽器人工驗收仍依原安排待進行。

## v0.2.2：失敗恢復與讀取邊界

開啟壞檔／取消新檔後，還原上一份已完成索引與工作狀態：時間窗、篩選、分組、釘選、詳情、已完成的分析結果。Esc 會走取消流程，舊 Worker 的延遲訊息不會覆蓋新的工作階段。恢復失敗時仍保留可重新開啟原檔的入口。

針對正式 app.js 與 Worker 的測試先重現壞檔後遺失原畫面，再確認可還原並繼續讀取原始事件。另驗證取消／Esc、保留縮放時間窗與篩選、忽略退休 Worker 的延遲 ready。此測試使用 DOM／Canvas 與檔案系統替身，不能當作瀏覽器驗收。

新增兩項整合測試，總數 38 項：依檔頭解 gzip（含大寫副檔名、壓縮內容使用 .json、錯誤 .gz），未回報 quota 時仍可匯入；注入磁碟索引初始化失敗後，關閉檔案並刪除未完成 session，下一次匯入可成功。原先誤判空間不足與留下 session 的測試均已先確認失敗，再修正通過。

解析與關聯核心未修改，來源 SHA-256 仍符合 v0.2.1 的 3 GB 引擎測試；本次 Worker 的新檔頭、配額與恢復流程由相依整合測試驗證，並未聲稱有瀏覽器效能數據。
