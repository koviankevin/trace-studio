# 內網實際 Trace 驗收

這份表對應目前四類驗收中的「真實 CORE 分析正確性」。公開版已用合成資料驗證功能與大檔操作；實際硬體欄位和模型／最佳化語意，需由能取得內網資料的人員核對。狀態在實測前維持「待內網驗收」。

適用版本：v0.14.2；應用來源 historical-revision。後續修改可記錄自己的來源 commit。既有條件與數據見 [驗證紀錄](VERIFICATION.md) 及 [效能紀錄](PERFORMANCE.md)。

## 準備

將儲存庫的整個 dist/ 部署至內網 HTTPS 靜態站台，保留相對路徑。前端使用者以桌面 Chrome／Edge 開啟，不需要 Node 或套件安裝。預設擴充宣告見 [custom.js](../dist/extensions/custom.js)。

若在開發電腦本機核對，可於儲存庫根目錄使用 Node.js 24.5 以上執行：

~~~sh
node server.mjs
~~~

瀏覽 http://127.0.0.1:4318 。在頁面以「開啟 Trace」選擇內網 JSON／JSON.gz／tar.gz。原始 JSON、位址、模型名稱與完整分析匯出保留在內網；回報本表的結果摘要即可。

先挑一個能人工核對的小時間範圍、一筆已知事件、一個已知 TfliteID／LinkId 和一對已知記憶體區段。記錄程序／核心與範圍，讓參考結果和網站使用相同條件。

## 核對表

| 項目 | 操作與參考資料 | 通過條件 |
| --- | --- | --- |
| 事件與欄位 | 點選已知事件，對照完整原始 JSON、Args、事件名、PID／TID、ts／dur；B/E 事件同時查看兩端。 | 原始值保留；缺名時的短 TID 可追溯回原始值。時間輸入依 Chrome JSON 的 µs 解讀，顯示單位換算一致。 |
| 同 TfliteID／LinkId | 從事件詳情進入同 ID 分析，在相同時間窗與核心條件下，與內網已有工具或人工清點比對；有零值、Identity 或欄位衝突時一併抽查。 | 事件集合、數量和核心分布符合來源。ID 重用時使用相同時間範圍；明確欄位與 Identity 衝突可從來源路徑查明。 |
| MemoryRanges 區段 | 對照同物件、同編號的 Range Start／Range End／Size／Location，再查看已知輸入／輸出區段的重疊結果。 | 尾端定義有 Size 或來源格式支持；重疊 bytes 正確。來源不足或 Size 不一致時保留不確定資訊，沒有把相同位址當成配置生命週期或必然因果。 |
| 已知關聯 | 選一對已知事件，確認同址候選或明確 flow／define-use，檢查跨核心跳轉和單筆連線端點。 | 類型與來源鍵相符；「同址候選」和明確依賴可區分，線頭及跳轉落在正確事件。候選有界／取樣時保留其限制。 |
| 優化版本比較 | 如有 2–3 份同圖版本，使用明確可對應的 TfliteID，分別核對各檔相同定義的範圍、數量與區段累計；再檢查多 ID 或整圖彙整。 | 差值與內網參考一致。累計包含重疊，不作 self time 或核心使用率；目前依相同 ID 對齊；ID 已重編的版本先標記無法直接比較，由內網定義映射／擴充並驗證後再判讀。 |

欄位格式差異可依 [擴充介面](EXTENSIONS.md) 調整。ID／Identity／MemoryRanges 的辨識入口在 [argument-facts.js](../dist/argument-facts.js)，原始欄位摘要在 [event-summary.js](../dist/event-summary.js)；一般新增顯示或分析可先使用 extensions/custom.js。調整後重新核對受影響列，並記錄修改的來源版本。

## 回報格式

複製以下文字填寫，原始事件與匯出檔留在內網：

~~~text
應用版本／來源 commit：
瀏覽器版本：
資料類型：真實硬體 trace
參考結果來源：內網工具／人工清點（填方式即可）
比較條件一致：是／否／待確認

事件與欄位：通過／有差異／未測
同 TfliteID／LinkId：通過／有差異／未測
MemoryRanges 區段：通過／有差異／未測
已知關聯與跳轉：通過／有差異／未測
優化版本比較：通過／有差異／未測／無比較檔

差異類型：欄位未辨識／集合或數量／單位／端點／分組／其他
差異摘要：只描述可對外提供的結構與預期／實際結果
整體語意驗收：通過／待修正／證據不足
~~~

欄位不適用時標註理由。沒有來源資料或參考結果的列保留「未測」；內網人員完成核對後，再依回報更新這一項驗收狀態。
