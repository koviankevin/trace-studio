# 3 GB 引擎基準測試

## v0.12.0：長字串串流掃描

在字串內，只有引號與反斜線影響事件邊界。新版使用原生搜尋跳過連續內容，並在同一 chunk 內保留下一個反斜線位置，避免大量短鍵值反覆搜尋整個 chunk。JSON.parse 仍負責完整語法驗證，原始字串與事件內容不改寫，磁碟格式及既有快取不變。

同機、同語料每種三次的 parser-only 中位數：長字串 810.77 → 216.72 ms；跳脫／中文／結構文字 798.18 → 623.88 ms；大量短欄位 1,064.80 → 970.69 ms。約 64 MiB 字元語料，只保留約 1 MiB batch，不是整檔載入；每次核對事件數及原始字元數。詳見 [前後數據與來源](parser-benchmark-2026-10-30-v0.12.0.json)，執行 node scripts/benchmark-parser.mjs 可量測目前來源；基準 commit 為 historical-revision。

最終 Node 3 GB 建索引 27.27 秒、程序 RSS 抽樣峰值 348.09 MB；80 視窗冷／熱 P95 85.04／77.57 ms，位址查找 2.49 ms。上一版建索引觀察為 43.11 秒，跨時次仍受負載影響。[完整數據](benchmark-2026-10-30-v0.12.0.json)。重新跑百萬 counter：7.92 秒、RSS 抽樣峰值 347.45 MB，80 個視窗全部保留正確極值，冷／熱 P95 26.67／28.41 ms。[counter](counter-benchmark-2026-10-30-v0.12.0.json)。百萬筆單址查找再驗證中段／尾段約 796／1,165 ms，每次核對前後相鄰事件、原始候選驗證 64 筆、讓出 51／75 次。[同址數據](relation-benchmark-2026-10-30-v0.12.0.json)。

瀏覽器實際 File 匯入同為 3,000,583,032 bytes／2,932,637 筆。localhost:4318 新版一次為 46.17 秒；另在乾淨的 localhost:4320 來源，以同一份 File 依序執行前版、新版，應用內回報 69.70 → 29.33 秒。前版檔案選取自動化曾異常等待，該等待在 File 交給應用前，未列入 importTime。這是一次順序對照，沒有隨機化或排除 OS 快取、磁碟及背景負載，不能據此保證每次或任意 trace 的加速比例，也未量測整個使用者選檔流程。見 [同源對照](parser-browser-comparison-2026-10-30-v0.12.0.json) 及 [實際操作](parser-browser-2026-10-30-v0.12.0.json)。

匯入後核對 Task 0 的完整 Args、F 聚焦及相鄰 Task 8；再開啟含非 JSON 空白的錯檔，原 3 GB Trace、Task 8 選取與 770–940 µs 時間窗均復原。這些是功能證據，不是新版畫面 P95、FPS 或完整瀏覽器峰值 RAM。


## v0.11.0：同址候選與合作式查找

最終 core.js／relations.js：3,000,583,032 bytes、2,932,637 筆 X 事件，Node Worker 建索引 43.11 秒、程序 RSS 抽樣峰值 333.58 MB。80 個視窗冷應用快取中位數／P95 7.86／75.28 ms、熱快取 6.45／78.18 ms，單次稀疏位址查找 10.58 ms／14 筆。見 [原始數據與來源 SHA-256](benchmark-2026-10-30-v0.11.0.json)。沒有用跨時次差異宣稱加速或穩定上界；core.js 與 v0.9.0 相同，百萬 counter 極值基準沿用該版來源綁定紀錄。

另以 Node 真實檔案系統產生一百萬筆全部共用同一位址的 X 事件並還原索引：建立 5.96 秒、程序 RSS 抽樣峰值 225.45 MB、磁碟約 193.89 MB。中段／尾段查找 730／1,333 ms，各讓出執行 48／88 次，核對前後相鄰事件並只驗證 64 個原始候選、回傳 64 筆。首次讓出後取消約 14.58 ms。yield 期間直接呼叫的可見查詢為 0.36／0.22 ms；這個量測不是 Worker 訊息延遲，實際訊息交錯另由 integration 案例驗證。見 [密集同址數據](relation-benchmark-2026-10-30-v0.11.0.json)，可用 node scripts/benchmark-relations.mjs 1000000 重跑。

同址候選預選最多 256 個參照，原始候選驗證預算 256，唯一結果 64。仍需掃描匹配的索引區塊，因此查找不是常數時間；B/E 端點排名也不是全域最近配置區段保證。合作式約 8 ms 預算不能中斷單次同步讀取或 JSON.parse。上述是合成資料的 Node 程序觀察，不是瀏覽器總 RAM、OPFS 或畫面延遲；本輪瀏覽器只驗證既有 3 GB 快取可用與關聯操作，沒有重標舊 File 匯入秒數。

新字典保留完整名稱鍵，限定 8 MiB UTF-16 字元預算與 65,536 項、單名 4,096 字元。超出時，只有需要顯示／搜尋的事件才讀回原名；搜尋每段約 8 ms 讓出 Worker 並檢查取消。單次讀取／JSON.parse 與排程本身不受這個時間預算硬性保證。基本分析仍以索引為主，名稱不完整者明示排除於名稱排行，僅為最長 50 筆補讀原名。Args 分析另按完整原名彙整並限制字元預算，避免將相同預覽誤認成同名。


最終版另從既有 OPFS 還原 3 GB 合成資料，1280×720 visible 視窗下五組放大／縮小完成 10 次 Canvas 更新：P50 61.5 ms、P95 85.2 ms，Worker P95 7.7 ms。這是短操作觀察，不是穩定延遲上界；完整原始樣本、來源雜湊、限制與 P95 重算見 [v0.9.0 runtime](runtime-browser-2026-10-29-v0.9.0.json)。

## v0.8.0：瀏覽器更新延遲

新增可手動開關的本機效能記錄，不設輪詢計時器，不記錄檔名或事件內容。從範圍／軌道狀態更新開始，包含 25 ms debounce、佇列、Worker 查詢與主頁 Canvas 提交；尚未經過匹配查詢回覆的舊畫面不會被算成完成。只計最新狀態的完成樣本，連續操作被合併的更新與背景分頁略過另行計數。P50／P95 用最近最多 512 筆的排序後第 floor((N−1)×p) 筆。

Windows 內嵌 Chromium 156、瀏覽器回報 visible、1280×720；從本站 OPFS 還原已保存的 3,000,583,032 bytes／2,932,637 筆 X 事件／8 軌道合成 Trace，沒有重新解析原檔。先全覽，再交替放大／縮小 15 組；另一輪先放大一次，再交替 D／A 平移 8 次並等動畫尾端完成。完整時間樣本、上下文、來源 SHA-256 與可重算摘要見 [runtime-browser-2026-10-29-v0.8.0.json](runtime-browser-2026-10-29-v0.8.0.json)。

| 項目 | 縮放 | 鍵盤平移期間（含初次放大） |
| --- | --- | --- |
| 完成 Canvas 更新 | 30 筆 | 21 筆 |
| 被合併的狀態更新 | 0 | 17 |
| Canvas 更新 P50 / P95 / 最大值 | 53.2 / 66.2 / 83.5 ms | 56.3 / 67.7 / 70.1 ms |
| Worker 查詢 P50 / P95 | 4.3 / 7.3 ms | 4.1 / 5.6 ms |
| 主頁長任務 | 0 次 | 0 次 |

這不是 compositor 呈現、實體按鍵起點、FPS 或 INP 的量測；被合併的輸入沒有各自完成畫面。樣本數有限，快取為熱，資料形狀單一，不能保證任意 3 GB Trace 的延遲，也不能用兩輪差異宣稱演算法加速。較早的 31 筆縮放 UI 觀察為 P50 50.2 ms、P95 74.6 ms；增加 JSON 原始時間樣本後的一輪為縮放 P95 51.5 ms、平移 65.0 ms。補上背景切換時清除在途觀測後，再取得表中的最終量測；保留差異而不把單輪結果視為穩定上界。

長任務使用 [W3C Long Tasks API](https://www.w3.org/TR/longtasks-1/) 的主頁觀測；本輪沒有觀測到 ≥50 ms 任務，並非證明整個瀏覽器沒有長任務。JS heap 使用瀏覽器可選的 performance.memory；[此 API 可能忽略 Worker heap 或計入共用 heap](https://developer.mozilla.org/en-US/docs/Web/API/Performance/memory)，因此只標成近似抽樣，不當作完整瀏覽器的峰值 RAM。本輪主頁抽樣約數十 MB，不涵蓋 Worker、原生／GPU 或磁碟頁面快取。

v0.8.0 的 core.js／relations.js 未修改，仍由測試核對 v0.7.1 引擎與百萬 counter 的來源雜湊。上述瀏覽器更新量測與既有 Node 匯入基準分開，沒有重標舊解析秒數。

v0.7.2 僅調整詳情面板的空間分配；解析／索引／關聯核心與 v0.7.1 來源雜湊相同，沿用下列基準。面板高度修正以瀏覽器幾何與實際鍵盤操作另行驗收。
