# 時跡 Trace Studio

**把時間，看清楚。** 純網頁 Chrome Trace JSON 工作台：時間軸、原始事件資訊、位址關聯，以及為大檔設計的本機磁碟索引。

**[開啟時跡](https://koviankevin.github.io/trace-studio/)** · [操作參考](https://perfetto.dev/docs/visualization/perfetto-ui) · [效能測試](docs/PERFORMANCE.md)

目前為 v0.5.0。解析、索引、Args 分析、擴充介面及開檔啟動流程已有自動化測試；**瀏覽器畫面、OPFS 實際效能與操作仍待人工驗收**。尚未證實比 Chrome tracing 或 Perfetto 更快；本專案的目標是在熟悉的操作上提供更清楚的資訊與大檔路徑。

## 使用

以最新版桌面 Chrome / Edge 開啟網站，選擇「開啟 Trace」或拖入 `.json` / `.json.gz`。支援根層事件陣列，以及 `{ "traceEvents": [...] }`。沒有檔案時會載入清楚標示的合成示範資料。

需要 HTTPS（本機開發可用 localhost）、OPFS 支援及足夠的瀏覽器儲存空間。檔案在瀏覽器內處理，不會上傳伺服器；沒有分析追蹤、外部字型或 CDN 依賴。快取保留在本瀏覽器的本站儲存區，下次開啟會還原最後完成的索引。左側「Trace 快取管理」可還原之前的索引、逐份清理，或保留目前 Trace 並清除未使用快取，不會改動原始檔案。

開啟壞檔或取消新檔時，會嘗試還原上一份 trace 的時間範圍、篩選、分組、釘選與選取。Esc 與取消按鈕使用相同流程。Gzip 依檔頭辨識，支援大寫副檔名；瀏覽器未提供儲存額度時不會誤判為零，實際磁碟不足仍會回報錯誤。磁碟初始化或解析失敗會移除該次未完成的索引；強制停止 Worker 的取消仍可能留下未完成快取，可從清單辨識並回收。

每份索引的開啟／匯入／刪除以同源 [Web Locks](https://www.w3.org/TR/web-locks/) 協調，另保留 [OPFS 檔案獨占鎖](https://fs.spec.whatwg.org/#api-filesystemfilehandle-createsyncaccesshandle)。清理會跳過其他分頁使用中的快取，不會強制搶鎖；關閉分頁或 Worker 後可重新清理。缺少 Web Locks 的環境不會冒險刪除未完成匯入。清單只讀取小型摘要與檔案大小，不把大檔事件載入記憶體；舊版大型索引缺少摘要時可能暫時只顯示識別碼。

## 功能

- Canvas 時間軸與可見軌道虛擬化、密度全覽、以滑鼠位置為中心縮放。
- X 完整區段、B/E 同步配對、i/I/R 即時事件、C counter 曲線；其他 phase 保留為標記。
- 程序與執行緒名稱、軌道篩選、釘選到頂部、雙擊軌道名稱展開高度。
- 程序／核心分組收合、群組活動概覽、自然排序並相鄰排列 `work` 軌道，關聯跳轉會自動展開目標組。
- 預設緊湊工作台：薄工具列、可收合側欄、單層軌道約 32 px、時間軸填滿可用高度；可切換舒適列高。
- 可拖曳高度的下方事件詳情，集中顯示 trace 提供的 Core／Flow／Op ID、shape、tile、記憶體流量與來源建議。
- 事件名稱搜尋、最長 20 筆事件、完整原始欄位與 args、metadata、複製原始事件 JSON。
- 精確 address 關聯、標準 flow ID 與明確 defines / uses 關聯；點選跳轉及時間軸連線。
- 亮色與深色模式、指令選單與核心 Perfetto 操作。
- 背景 Trace 分析：完整 trace／目前範圍／指定群組、事件與各核心累計時間、長事件定位、近似 P95、取消及 JSON 匯出。
- 數值曲線集中分組；事件依名稱規則以淡色區分計算、搬移、等待、框架等，選取外框另外標示。
- 事件 Arguments、巢狀欄位、配對事件及原始 JSON 預設展開。一般軌道不顯示重複 Thread 標示，ID 保留於提示與詳情。
- 預設軌道編號不加 `#`。事件缺少名稱或只有空白時使用 TID，省略重複的 PID／程序名稱前綴，例如 `CORE0` + `CORE0_COMPUTE` 顯示 `COMPUTE`。數字 TID 不相減；原始 JSON 和明確的事件名稱不改寫。舊快取也會按需核對並套用補名。
- Args 分析：同 TfliteID／LinkId 集合、跨核心統計、MemoryRanges 範圍與輸入／輸出對應；點選結果返回事件，支援取消、分頁與重複查詢快取。
- 給內網 AI 的程式擴充入口：[custom.js](dist/extensions/custom.js) 與[擴充說明](docs/EXTENSIONS.md)，可新增分析、事件欄位及配色。

## 多核心工作台

先依 PID 分程序；同一程序若混有 `CORE0`／`CORE1`、`CPU0`／`CPU1` 等具名軌道，再按名稱中的核心／加速器前綴分組。單一程序本身已代表一個核心時，不重複多加一層。原始名稱保留在 tooltip 和事件資料，子軌道標籤可省略群組已表達的核心前綴。

多組資料起初收合，點選箭頭或整組活動概覽展開；「展開全部／收合全部」可快速切換。輸入篩選條件會暫時展開符合的組，清除篩選後保留先前收合狀態。釘選軌道不會因父組收合消失；事件搜尋、address 關聯及 F 聚焦會展開目標的父組。

收合概覽僅合併既有索引摘要，**不讀取整份原始事件，也不代表精確事件數、利用率或瓶頸**。自訂名稱若不含可辨識核心前綴，仍會保留在原 PID 程序內，不從工作單元編號猜測核心。

左上角選單可載入四核心、每核心 28 軌道的 **合成 CORE 示範**。所有時間、shape、流量及 address 都是示意值，並非量測結果。底部欄位表只整理原始 args 明確提供的值；「來源標示瓶頸／來源建議」也是 trace 自帶的文字，不是工具推論。

緊湊模式保留約 13 px 軌道名稱、12 px 時間軸事件字體，移除逐列重複的 PID／TID／事件數留白；這些資料可在 tooltip／詳情查看。巢狀事件會按需要增加列高，雙擊軌道仍可展開。事件詳情面板頂部可拖曳調高，或聚焦分隔線以方向鍵調整；Q 可切換顯示。

折線 counter 集中在「數值曲線」，再依原程序／核心分組，不和區段軌道交錯。來源 PID／軌道識別仍保留，釘選、篩選及關聯跳轉同樣適用。

Counter 縮小顯示時保留摘要區間的首尾與最大／最小樣本，再按畫素聚合，避免短暫尖峰被第一筆樣本蓋掉。視窗邊界與放大範圍會讀取確切索引。線段可用視窗外相鄰樣本裁切連接，但插值只用於畫面，不會成為事件或分析資料；沒有相鄰量測時不延伸曲線。小數刻度保留有效位數，常數置中顯示。舊快取仍可正確查詢，重新匯入可建立新的極值摘要及 counter 關聯索引。

## 多檔保存、切換與比較

「開啟 Trace」或拖放可一次選擇多份檔案，依序建索引；完成的檔案出現在頂部分頁列。每份事件與索引自動保存在本站 OPFS，切換不必重選原始檔。重新整理會還原最後一份，保存清單與最近 50 份的時間範圍、篩選、釘選、收合與捲動位置也會保留。取消或壞檔會停止待匯入佇列，已完成資料保留。

小檔索引預設以 64 MB 為門檻，可選關閉／32／64／128／256 MB。判定使用原始檔大小與解壓後事件＋索引磁碟量的較大值，避免壓縮大檔誤判。小檔切換保留已讀的索引及磁碟讀取快取，最多 3 份閒置 Trace，總資料量預算為門檻兩倍（上限 512 MB）；這是資料量估算，不是固定 RAM 配額，原始事件仍留在磁碟。大檔與被淘汰的小檔從本機索引重載，不重新解析原始 JSON。重新整理後首次還原也需讀取本機索引。

頂部「比較」可選 2–4 份已保存的 Trace 與相同 TfliteID，比較事件數、首末跨度、相對第一份有結果檔案的跨度差、累計時間、核心／PID、同名事件與各記憶體空間的宣告 Size／輸入輸出區段。每份時間列以該 ID 的首個事件為 0，最多列出索引順序前 100 筆再按時間排列，點選可切回原 Trace 的事件；統計涵蓋全部符合事件。可取消或匯出比較 JSON，執行期間目前時間軸仍可查詢。

同 ID 可能重用：目前比較各檔案完整時間範圍內的同 ID 集合，沒有自動區分多次推論，也沒有建立跨檔因果鏈。名稱／記憶體彙整有上限，達上限會標示；時間列只是有限明細，不能當成完整事件圖。其他瀏覽器分頁占用某份索引時會保留該檔案並回報忙碌，仍呈現其他檔案的比較結果。

保存限於同一瀏覽器的本站儲存區；清除本站資料、瀏覽器回收空間或換瀏覽器後需重新匯入原檔。Trace 快取管理可明確刪除保存資料，關閉或淘汰記憶體快取不會刪檔。比較結果需重算或自行匯出保存。

## 單檔 Trace 分析

左側「Trace 分析」可選完整 trace，或先在時間軸調整時間窗／篩選後分析目前範圍；也能指定程序／核心／數值群組，設定長事件門檻（ms）。掃描在 Worker 進行，每八個索引區塊讓出執行緒，支援取消；畫面仍能提出視窗查詢。

結果包含區段數、counter 樣本數、標記數、各名稱／軌道／群組累計時間、平均與最長區段，以及對數分桶的 P95 近似上界。跨時間窗的區段裁切至 `[start,end)`；最長區段可跳回時間軸。可匯出本機 JSON 報告。

**累計時間包含巢狀與重疊，不是 self time、union busy time 或核心使用率，也不能直接當作關鍵路徑／因果瓶頸。** P95 是估計，不是精確排序的百分位數。名稱排行最多 100 筆、最長事件最多 50 筆，軌道表顯示前 100 筆；完整軌道統計保留在匯出結果。

基本統計只掃固定寬度索引。勾選「解析 Args」後，另在 Worker 逐筆讀取選定範圍的原始事件，蒐集同 TfliteID／LinkId 的事件、時間與核心／程序分布。也會解析 Identity 內的識別欄位；明確欄位優先，衝突會標示。B/E 兩端 Args 都納入，counter 的多個數值欄位不會把同一原始事件重算多次。這項掃描較耗時，不會在匯入或時間軸查詢時自動執行，可取消並縮小範圍。

選取事件的詳情可直接按「分析同 TfliteID／LinkId」或「比對記憶體範圍」。`MemoryRanges` 同一物件內相同編號的 Range Start、Range End、Size、Location 會配成區段，以 Size 核對含尾端／不含尾端的定義；不一致會提醒。記憶體候選預設限定同程序／已知核心，列出重疊 bytes、Location、輸入／輸出方向及時間先後，也可勾選跨程序／核心。

每類識別欄位最多彙整 16,384 組，顯示前 100 組；指定 ID 或記憶體條件仍掃描完整選取範圍。符合事件每頁 100 筆，依索引順序列出；換頁會背景掃描，最近 8 份結果可重用。單事件解析最多 4,096 欄位、8 層及 32 個記憶體區段，達上限會標示，原始 JSON 保留完整。

同 ID 可能重用，不等於唯一一次推論。記憶體重疊與輸出→輸入只是對應候選，沒有 allocation 生命週期不能證明因果；Size 累計可能包含重用，不是實際 memory traffic。

給內網 AI 的擴充可使用相同的 Args 解析模組，加入專案專用的 Flow、shape、traffic 或其他分析；該擴充的資料定義、成本與依據需自行驗證。網站預設不連內網或遠端 AI；「內網擴充」是可維護的程式介面，不是資料來源連線設定。

## 位址關聯

自動掃描 `args` 內的 `address`、`addr`、`ptr`、`pointer`（含常見底線／駝峰命名與巢狀欄位），以及形如 `0x1234` 的十六進位字串。精確位址會統一大小寫、進位及前導零：`"0x0000ABCD"`、`"0xabcd"`、`43981` 可以連到同一鍵。

```json
{
  "traceEvents": [
    { "name": "Allocate", "ph": "X", "pid": 1, "tid": 1, "ts": 0, "dur": 10,
      "args": { "address": "0x0000ABCD", "defines": "buffer-1" } },
    { "name": "Read buffer", "ph": "X", "pid": 1, "tid": 2, "ts": 20, "dur": 5,
      "args": { "ptr": "0xabcd", "uses": ["buffer-1"] } }
  ]
}
```

**相同位址只代表比對線索。** 快速關聯索引比對精確位址，Args 分析則可按需比對 MemoryRanges 範圍重疊；兩者都不推論物件生命週期或隱含的 define/use。不同程序可能有相同虛擬位址，記憶體也可能重用，請搭配 PID、核心、時間及原始資料判斷。明確 `defines` / `uses` 保留角色；Chrome `s/t/f` 依 category、scope 與 ID 比對。

大於 JavaScript 安全整數範圍的 address / ID 請以字串表示；原始 JSON 可完整複製，但以數字記錄的超大整數在物件解讀時可能失真。每事件最多索引 32 個關聯鍵，巢狀掃描至 6 層，每次顯示最多 64 筆候選、最多繪製 16 條連線。這些限制不截斷儲存的原始事件。

## 大檔架構

`File.stream → TextDecoderStream → Worker 串流 parser → OPFS 原始事件 / 固定寬度索引 / 關聯索引 → 視窗查詢 → Canvas`

不對整份檔案執行 `JSON.parse()`，也不把數百萬個完整事件交給 UI。事件索引為 64 bytes / 筆，按軌道以 4,096 筆排序分塊；每塊保留摘要，縮小時依解析度聚合。原始事件與 args 存磁碟，點選後才讀取。主索引待寫事件最多 16,384 筆，區塊讀取快取最多 24 塊。

**3 GB 合成資料已完成 Node 磁碟介面引擎測試：40.7 秒建索引、約 344 MB 程序 RSS、冷查詢 P95 59.2 ms。這不是瀏覽器測試。** 詳見 [測試條件與原始數據](docs/PERFORMANCE.md)，不能直接視為所有真實 trace 或瀏覽器的保證。

目前限制：單筆 JSON 資料最多 32 MiB，metadata 摘要共 4 MiB，最多 8,192 軌道／65,536 個摘要名稱／100,000 個未結束 B 事件。超出摘要名稱上限仍保留原始事件，但名稱搜尋覆蓋不完整。時間戳依 Chrome 格式解讀為 µs；`displayTimeUnit` 僅保留為 metadata，不改變輸入單位。逆序 trace 正確性有測試，但因分塊範圍可能重疊，查詢會讀取更多磁碟資料。

尚未支援 Perfetto protobuf、SQL、stack sampling 重建、非同步區段重建、多檔合併與精確 busy-time／關鍵路徑統計。密集畫面顯示代表事件與聚合筆數，不是每筆事件的獨立像素；可放大或搜尋具名事件。耗時排行為 inclusive duration，不是 self time。

## 開發與測試

無套件安裝與建置步驟。開發與測試使用 Node.js 24.5 以上（跨 Worker 鎖定測試需要 LockManager）；公開網頁使用者不需要安裝 Node：

```sh
node server.mjs
node --test tests/*.test.mjs
node scripts/benchmark.mjs 3000000000
```

開啟 `http://127.0.0.1:4318`。效能腳本把測試快取寫入作業系統暫存區並在結束時清除，輸出到忽略的 `evidence/benchmark.json`。基準測試需約 3.2 GB 可用磁碟空間；壓縮輸入在瀏覽器中可能展開得更大。

發布腳本先跑解析／索引測試，再以 `git subtree split` 把相同來源 commit 的 `dist/` 推送至 `gh-pages`。GitHub Pages 使用分支發布；目前登入憑證不具 `workflow` scope，因此未加入自訂 Actions workflow。瀏覽器人工驗收項目另見 [驗收清單](docs/VERIFICATION.md)。
